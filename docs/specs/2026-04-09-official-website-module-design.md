# 官网站点模块设计

> 本文是 [`2026-03-27-model-api-platform-design.md`](./2026-03-27-model-api-platform-design.md) 的模块细化文档之一。
> 本文只描述官网站点模块，不重复总设计中的项目背景、商业定位与整体 MVP 范围。

## 1. 模块目标与非目标

### 1.1 模块目标

官网站点面向未登录用户、潜在付费用户和首次接入的开发者，承担以下目标：

- 清晰表达产品定位、价格优势和兼容性价值
- 提供最短路径的注册、登录和购买入口
- 提供开发者接入说明和文档入口
- 为后续控制台与支付转化承接流量

### 1.2 模块非目标

官网站点不承担以下职责：

- 不负责套餐状态、额度状态或账户可调用性判断
- 不负责请求级 usage 查询和统计分析
- 不负责订单状态的最终确认和权益发放
- 不负责模型路由、上游配置或后台运营能力

## 2. 职责边界与上下游依赖

### 2.1 职责边界

官网站点只处理公开信息展示和轻量业务入口，不持有复杂业务状态真相。

可承接的动作包括：

- 展示首页、价格、兼容性说明、模型列表、文档内容
- 提供注册、登录入口
- 提供控制台入口
- 发起购买入口

不应在官网前端自行推导或决定：

- 用户当前套餐是否有效
- 用户额度是否耗尽
- 订单是否支付成功
- 账户是否被暂停调用

### 2.2 上下游依赖

官网主要依赖以下模块或服务：

- 认证服务：提供注册、登录、登录态识别
- 计费与订阅核心：提供公开套餐信息或购买发起能力
- 用户控制台：承接登录后的账户操作
- 文档内容来源：提供 API 接入说明和兼容说明

## 3. 功能拆分

### 3.1 首页

首页负责回答用户最核心的三个问题：

- 这是什么产品
- 为什么价格更低
- 为什么可以低成本迁移现有 OpenAI / Anthropic 调用

首页应突出以下信息：

- 面向美国独立开发者和小团队
- 提供 OpenAI 兼容 API 和 Anthropic 兼容 API
- 价格透明，套餐规则清晰
- 适合以代码调用为主的集成场景

### 3.2 价格页

价格页负责解释平台收费方式和套餐规则，应至少包含：

- 套餐名称
- 套餐价格
- 周期说明
- 套餐内额度
- 超额后暂停调用说明
- 当前支付方式为 PayPal 自动开通的一次性购买

价格页必须避免含糊表述，不能让用户误解为可透支调用或自动续费已上线。

### 3.3 兼容性说明页

兼容性说明页负责降低迁移门槛，重点说明：

- 支持 OpenAI 兼容调用
- 支持 Anthropic 兼容调用
- 基础认证方式
- 模型名使用方式
- 常见接入差异和错误说明

### 3.4 模型列表页

模型列表页用于向用户展示当前公开可用的模型能力范围，应至少包含：

- 对外模型名
- 协议归属
- 可用状态
- 简要说明

第一版不公开上游供应商内部配置、真实模型标识或路由策略。

### 3.5 文档页

文档页提供开发者接入的最短路径，至少包含：

- OpenAI 兼容接入示例
- Anthropic 兼容接入示例
- 鉴权方式说明
- 常见错误说明
- 控制台与 API Key 获取路径说明

### 3.6 登录、注册与购买入口

官网应在显著位置提供：

- 注册入口
- 登录入口
- 进入控制台入口
- 套餐购买入口

官网可以触发购买动作，但订单创建、支付状态确认和权益发放必须由后端业务服务处理。

## 4. 核心数据对象

官网模块主要消费只读或轻状态数据，不拥有复杂业务主数据。

建议官网使用以下公开数据对象：

- 公开套餐摘要
- 公开模型列表
- 兼容协议说明摘要
- 登录态摘要

这些对象只用于页面展示，不包含内部运营字段，例如：

- 上游供应商凭证
- 上游真实模型 ID
- 成本信息
- 内部风控状态

## 5. 关键接口与页面动作

官网模块需要的关键能力包括：

- 获取公开套餐列表
- 获取公开模型列表
- 获取公开文档内容或文档索引
- 获取当前登录态摘要
- 发起注册和登录跳转
- 发起购买流程

其中“发起购买流程”只表示创建购买入口，不表示支付成功。支付成功与否以后端订单状态为准。

## 6. 关键流程

### 6.1 首次访问到注册

1. 用户访问首页或价格页
2. 阅读产品价值与价格规则
3. 点击注册
4. 进入认证流程
5. 注册成功后进入控制台或回到购买入口

### 6.2 首次访问到购买

1. 用户访问价格页
2. 选择目标套餐
3. 若未登录，则先完成注册或登录
4. 登录后进入购买发起流程
5. 后端创建订单并返回支付跳转信息
6. 用户跳转到 PayPal 完成支付
7. 支付结果由控制台或订单查询页承接显示

### 6.3 首次访问到技术接入

1. 用户访问首页或兼容性说明页
2. 进入文档页
3. 阅读 OpenAI 或 Anthropic 兼容接入示例
4. 注册并进入控制台创建 API Key

## 7. 异常处理

官网模块至少处理以下异常场景：

- 套餐信息读取失败
- 模型列表加载失败
- 文档内容缺失或暂不可用
- 登录态识别失败
- 购买跳转创建失败

异常处理原则：

- 优先给出用户可理解的提示
- 提供明确后续动作，例如重试、进入控制台、联系支持
- 不暴露内部错误堆栈、内部服务名或敏感配置

## 8. 权限与安全约束

官网默认是公开访问模块，但仍需满足以下安全约束：

- 登录、注册和购买入口必须接入统一认证体系
- 公开接口不得泄露内部路由、上游凭证或成本信息
- 文档示例不得泄露真实生产密钥或内部模型映射
- 公开页面应具备基础反滥用能力

## 9. MVP 范围内与范围外

### 9.1 MVP 范围内

- 首页
- 价格页
- 兼容性说明页
- 模型列表页
- 文档页
- 登录/注册入口
- 购买入口

### 9.2 MVP 范围外

- CMS 内容运营系统
- 博客、新闻、活动营销系统
- 多语言站点
- 复杂 SEO 管理平台
- 在线客服或工单系统

## 10. 测试与验收重点

官网模块的验收标准应聚焦于转化和信息表达，而不是复杂交互。

至少验证：

- 用户能在首页清楚理解产品定位与兼容能力
- 用户能在价格页看到明确的套餐与超额暂停规则
- 用户能顺利进入注册、登录和购买入口
- 用户能在文档页找到 OpenAI 和 Anthropic 接入方式
- 官网不承担账户状态和支付状态的最终判断逻辑

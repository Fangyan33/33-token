# API 代理网关模块设计

> 本文是 [`2026-03-27-model-api-platform-design.md`](./2026-03-27-model-api-platform-design.md) 的模块细化文档之一。
> 本文只描述 API 代理网关模块，不重复总设计中的项目背景、商业定位与整体 MVP 范围。
> 与计费核心之间的接口边界与时序细化，见 [`2026-04-09-gateway-billing-interaction-design.md`](./2026-04-09-gateway-billing-interaction-design.md)。
> 涉及数据对象与表关系时，统一参考 [`2026-04-09-database-logical-model-design.md`](./2026-04-09-database-logical-model-design.md)。

## 1. 模块目标与非目标

### 1.1 模块目标

API 代理网关是平台对外 API 的统一入口，承担以下目标：

- 接收 OpenAI 兼容请求
- 接收 Anthropic 兼容请求
- 校验 API Key 和账户可调用状态
- 根据内部路由配置转发到上游模型服务
- 对上游响应进行兼容适配
- 记录请求级 usage 事件和计费事件
- 输出统一、稳定、可观测的错误结果

### 1.2 模块非目标

API 代理网关不承担以下职责：

- 不负责定义套餐、订单和支付规则
- 不负责持有账户权益状态的最终真相
- 不负责向用户展示请求明细或运营视图
- 不负责第一版自动故障切换或复杂智能路由

## 2. 职责边界与上下游依赖

### 2.1 职责边界

网关负责请求执行链路，不负责成为账务主系统。

网关可以执行：

- 协议解析
- API Key 鉴权
- 账户状态检查
- 套餐与额度检查
- 模型路由解析
- 上游转发
- 响应协议适配
- usage 事件记录

网关不应自行维护独立账务真相，例如：

- 不独立计算订单支付结果
- 不独立决定套餐激活规则
- 不绕过计费核心直接修改账户权益

### 2.2 上下游依赖

网关依赖以下模块或服务：

- API Key 服务：验证密钥是否存在、是否有效、所属账户
- 计费与订阅核心：提供账户状态、套餐状态、额度状态、账单周期归属
- 路由配置服务或后台配置源：提供模型路由与上游凭证引用
- usage/事件存储：接收请求级 usage 事件与计费事件
- 上游模型服务：如 Minimax、Kimi、GLM 等

## 3. 对外能力设计

### 3.1 协议入口

第一版网关必须提供两类兼容能力：

- OpenAI 兼容 API
- Anthropic 兼容 API

两类入口虽然协议不同，但在内部应收敛到统一执行链路。

### 3.2 对外模型名

平台对外公开稳定的模型名，用户以平台模型名发起请求。

平台模型名与上游真实模型标识解耦，内部可根据路由配置调整上游映射，但不应轻易破坏对外兼容承诺。

### 3.3 调用权限

第一版中，用户创建的 API Key 默认可调用当前平台开放的全部模型。

第一版不提供：

- API Key 级模型权限控制
- 用户自定义模型路由
- 用户可见的模型路由配置能力

## 4. 内部执行链路

统一执行链路建议如下：

1. 接收并解析兼容协议请求
2. 提取并校验 API Key
3. 获取 API Key 所属账户
4. 查询账户状态、套餐状态与额度状态
5. 校验当前请求是否允许放行
6. 根据模型名解析内部路由
7. 构造上游请求并调用上游模型服务
8. 接收上游响应并做协议兼容处理
9. 生成 usage 事件与计费事件
10. 返回标准化结果给客户端

关键原则：

- 额度耗尽必须在转发前阻断
- 计费事件必须和请求结果绑定
- 成功和失败请求都要留下标准化事件记录

## 5. 路由配置设计

第一版路由配置由内部维护，不向用户开放。

每条路由至少包含：

- 对外模型名
- 协议类型
- 上游供应商
- 上游真实模型标识
- 上游凭证引用
- 启用/停用状态
- 必要的请求适配策略

路由配置目标是让平台：

- 稳定提供统一模型名
- 能在内部替换上游实现
- 能通过后台停用异常模型入口

第一版不要求：

- 自动故障切换
- 智能成本优选路由
- 多上游并行竞速

## 6. usage 与计费事件设计

### 6.1 事件粒度

第一版必须以请求级事件形式记录 usage，不能只保留汇总值。

### 6.2 事件存储与实时判定数据

第一版不引入 Redis 作为额度判定前提。

`usage` 与计费相关数据建议分为两层，均存储在 PostgreSQL 中：

- 原始事件层：保存每次请求产生的 `usage_event` 和 `billing_event`
- 周期汇总层：保存账户在当前账单周期内的已用额度、剩余额度、暂停状态和更新时间

其中：

- 原始事件层用于审计、补账、对账、故障排查和后续重算
- 周期汇总层用于网关转发前的快速准入判断

网关在执行实时校验时，不扫描原始事件表，而是直接读取账户当前周期汇总记录。

### 6.3 关键字段

建议至少记录以下字段：

- 账户 ID
- API Key ID
- 协议类型
- 对外模型名
- 上游供应商
- 输入 token
- 输出 token
- 总 token
- 请求时间
- 请求结果状态
- 错误类型
- 请求耗时
- 内部成本信息
- 账单周期归属

对于周期汇总层，建议至少维护以下字段：

- 账户 ID
- 账单周期
- 套餐总额度
- 当前已使用额度
- 当前剩余额度
- 账户当前可调用状态
- 最近更新时间

### 6.4 事件用途

这些事件不仅用于用户汇总展示，还用于：

- 对账
- 补账
- 超额判断
- 成本核算
- 故障排查
- 后续细粒度报表扩展

## 7. 实时校验与扣减逻辑

### 7.1 转发前校验

第一版采用“转发前查汇总、请求后扣减”的方式，不做请求级额度预占。

网关在转发请求前，至少执行以下检查：

- API Key 是否有效
- 账户是否被停用
- 账户是否存在有效套餐
- 当前周期是否已暂停
- 当前周期剩余额度是否大于 0

如果账户已暂停或剩余额度小于等于 0，则请求必须在转发前直接阻断。

### 7.2 请求后扣减

请求完成后，网关根据上游返回结果生成原始 `usage_event` 和 `billing_event`，并更新账户当前周期汇总。

更新顺序建议为：

1. 写入原始事件
2. 更新账户当前周期汇总
3. 若累计后达到套餐上限，则将账户状态切换为已暂停

### 7.3 并发与边界

由于第一版接受“最后一个请求可能把额度打穿一点点”，因此不实现复杂的额度预占机制。

这意味着：

- 只要转发前读取到的剩余额度大于 0，请求就允许进入
- 某个请求在执行完成后，可能使账户从“仍有余额”变成“额度已耗尽”
- 从该请求之后的下一次请求开始，网关必须稳定阻断

该设计用更低复杂度换取更快落地，适用于当前 MVP 阶段。

## 8. 错误处理与标准化

### 8.1 账户与套餐错误

网关至少需要稳定返回以下错误类型：

- API Key 无效
- 账户无有效套餐
- 套餐已过期
- 套餐额度已耗尽
- 账户被停用

### 8.2 上游错误

第一版至少区分并记录：

- 上游超时
- 上游认证失败
- 模型不可用
- 上游限流
- 响应格式异常

### 8.3 标准化原则

- 对外错误响应保持协议兼容
- 对内错误分类保持统一编码和可检索性
- 不向外泄露内部供应商凭证和内部堆栈信息

## 9. 风控与安全约束

第一版至少具备以下基础能力：

- 基本速率限制
- 异常调用监控
- 手动封禁 API Key
- 手动封禁账户

安全设计要求：

- 网关必须在入口层进行密钥校验
- 高风险错误要可观测、可追踪
- 上游凭证不能暴露给客户端

## 10. 实现分层约束

由于本项目确定使用 Envoy AI Gateway 作为 API 代理网关，模块设计建议明确分层：

- Envoy AI Gateway：负责协议入口、流量编排、基础策略执行
- Go 业务服务：负责账户状态校验、套餐额度判定、usage 入库、计费事件处理、管理接口支撑

这样可以避免把复杂业务规则硬编码在纯网关配置中，也避免业务服务重复实现 API 接入层。

## 11. MVP 范围内与范围外

### 11.1 MVP 范围内

- OpenAI 兼容 API
- Anthropic 兼容 API
- API Key 鉴权
- 账户与额度检查
- 模型路由配置
- 上游转发
- usage 事件记录
- 标准化错误处理
- 基础限流与封禁

### 11.2 MVP 范围外

- 用户可配置路由
- API Key 级模型权限
- 自动故障切换
- 智能多上游调度
- 请求日志用户查询界面

## 12. 测试与验收重点

API 网关模块至少验证：

- OpenAI 兼容调用成功路径
- Anthropic 兼容调用成功路径
- API Key 无效时的阻断路径
- 套餐过期、额度耗尽、账户停用时的阻断路径
- 转发前基于周期汇总的准入判断正确
- 请求完成后原始事件写入与周期汇总扣减正确
- 额度由正数变为耗尽后，下一次请求可被稳定阻断
- 上游超时、限流、模型不可用等错误映射
- usage 事件字段完整性与准确性
- 账单周期归属正确性
- 限流与封禁策略实际生效

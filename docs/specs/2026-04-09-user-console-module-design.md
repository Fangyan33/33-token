# 用户控制台模块设计

> 本文是 [`2026-03-27-model-api-platform-design.md`](./2026-03-27-model-api-platform-design.md) 的模块细化文档之一。
> 本文只描述用户控制台模块，不重复总设计中的项目背景、商业定位与整体 MVP 范围。
> 涉及账户、套餐、API Key、订单与周期汇总的数据对象时，统一参考 [`2026-04-09-database-logical-model-design.md`](./2026-04-09-database-logical-model-design.md)。

## 1. 模块目标与非目标

### 1.1 模块目标

用户控制台面向已注册、已登录用户，承担以下目标：

- 展示账户当前可用状态
- 展示当前套餐与账单周期状态
- 展示账户级 usage 汇总
- 提供 API Key 管理能力
- 提供购买、升级和付款状态查看入口

### 1.2 模块非目标

用户控制台不承担以下职责：

- 不负责请求级日志查询
- 不负责 API Key 维度 usage 统计
- 不负责模型维度统计分析
- 不负责成为套餐、订单和额度状态的最终真相

## 2. 职责边界与上下游依赖

### 2.1 职责边界

用户控制台负责展示与发起动作，不负责自行计算核心账务状态。

控制台可以：

- 展示账户、套餐、usage、订单摘要
- 发起购买动作
- 创建和停用 API Key

控制台不应自行决定：

- 账户是否允许调用 API
- 订单是否支付成功并完成权益发放
- 套餐是否已正式激活或过期

这些结论必须来自后端业务模块。

### 2.2 上下游依赖

用户控制台依赖：

- 认证服务：提供登录态、账户身份识别
- 计费与订阅核心：提供套餐状态、周期信息、usage 汇总、订单状态
- API Key 服务：提供密钥列表、创建、停用
- 支付集成能力：提供购买发起与支付回跳状态承接

## 3. 功能拆分

### 3.1 账户概览

展示账户基础身份与账户总体状态，包括：

- 账户标识
- 注册信息摘要
- 当前账户状态
- 是否可继续调用 API 的说明性状态

### 3.2 当前套餐状态

展示用户当前最重要的权益信息，包括：

- 当前有效套餐
- 当前周期起止时间
- 套餐总额度
- 当前周期已使用额度
- 当前周期剩余额度
- 当前套餐状态

界面文案必须和网关错误语义一致，避免出现控制台显示正常、调用时却被拦截的冲突。

### 3.3 当前周期 usage 汇总

第一版仅展示账户级汇总，不做更细粒度拆分。

至少展示：

- 当前周期累计调用量摘要
- 输入 token 汇总
- 输出 token 汇总
- 总 token 汇总
- 账单周期归属说明

### 3.4 API Key 管理

第一版提供以下能力：

- 查看 API Key 列表
- 创建 API Key
- 停用 API Key
- 展示密钥创建时间、状态、摘要标识

创建 API Key 时，完整明文只允许展示一次，后续仅保留掩码形式。

第一版不提供：

- API Key 权限范围配置
- API Key 独立额度控制
- API Key 模型白名单

### 3.5 购买与付款状态

控制台提供：

- 套餐列表与购买入口
- 当前或最近订单状态
- 支付结果说明
- 异常订单的提示和联系支持入口

支付结果页应以系统订单状态为准，而不能以前端回跳结果直接判定为成功。

## 4. 核心数据对象

控制台主要消费以下数据对象：

- 账户摘要
- 套餐状态摘要
- 周期 usage 汇总
- API Key 摘要
- 订单摘要

控制台只读取必要字段，不直接暴露：

- 原始支付回调内容
- 请求级 usage 原始事件
- 内部运营修正规则
- 上游模型配置

## 5. 关键接口与页面动作

控制台需要以下关键能力：

- 获取账户概览
- 获取当前套餐状态
- 获取当前周期 usage 汇总
- 获取 API Key 列表
- 创建 API Key
- 停用 API Key
- 获取套餐列表
- 创建购买订单
- 查询订单状态

这些动作中，创建购买订单属于发起动作；订单支付成功与权益激活的确认仍由后端状态决定。

## 6. 关键流程

### 6.1 登录后查看账户状态

1. 用户登录进入控制台
2. 控制台读取账户概览和套餐状态
3. 控制台展示当前周期 usage 汇总
4. 若账户不可调用，则给出原因与后续动作

### 6.2 创建 API Key

1. 用户进入 API Key 管理页
2. 发起创建操作
3. 后端生成并返回新密钥明文
4. 控制台仅在创建成功当次展示完整明文
5. 用户确认保存后，后续页面仅展示掩码摘要

### 6.3 发起购买

1. 用户选择套餐
2. 控制台调用后端创建订单
3. 获取 PayPal 支付跳转信息
4. 用户完成支付后回到结果页
5. 控制台查询订单状态
6. 根据订单状态展示已激活、处理中或失败

## 7. 状态与异常处理

控制台需要对以下状态进行统一表达：

- 无有效套餐
- 待支付
- 已激活
- 已暂停
- 已过期
- 账户已停用

至少处理以下异常场景：

- 套餐状态读取失败
- usage 汇总延迟或暂不可用
- API Key 创建失败
- API Key 停用失败
- 订单创建失败
- 支付回跳成功但订单状态未同步

异常处理原则：

- 优先提示用户当前状态是否会影响调用
- 给出明确可执行动作，例如重试、刷新、重新购买、联系支持
- 不在前端伪造成功状态

## 8. 权限与安全约束

控制台是登录态模块，至少满足以下约束：

- 所有读写操作基于当前账户身份校验
- API Key 明文只允许单次展示
- 停用 API Key 需显式确认
- 购买、密钥创建、停用等关键操作应留下审计记录

第一版不引入团队、组织或多角色用户体系，默认单账户单用户视角。

## 9. MVP 范围内与范围外

### 9.1 MVP 范围内

- 账户概览
- 当前套餐状态
- 当前周期 usage 汇总
- API Key 列表、创建、停用
- 购买入口
- 订单状态查看

### 9.2 MVP 范围外

- 请求日志明细查询
- API Key 维度 usage 统计
- 模型维度报表
- 团队协作和多成员权限
- 高级财务对账视图

## 10. 测试与验收重点

控制台模块至少验证：

- 不同账户状态下的页面展示与后端状态一致
- API Key 创建后完整明文只展示一次
- API Key 停用后调用能正确失效
- 支付完成后控制台能正确反映订单与套餐状态
- usage 汇总口径与账单周期一致
- 当额度耗尽或账户暂停时，控制台提示与网关拦截语义一致

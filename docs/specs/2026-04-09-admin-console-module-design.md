# 管理后台模块设计

> 本文是 [`2026-03-27-model-api-platform-design.md`](./2026-03-27-model-api-platform-design.md) 的模块细化文档之一。
> 本文只描述管理后台模块，不重复总设计中的项目背景、商业定位与整体 MVP 范围。

## 1. 模块目标与非目标

### 1.1 模块目标

管理后台面向内部运营、技术支持和管理员，承担以下目标：

- 配置网关侧模型路由与上游凭证引用
- 管理套餐内容和可售状态
- 处理异常订单与补单
- 调整账户套餐与账户状态
- 查看运营所需的账户、订单和 usage 汇总

### 1.2 模块非目标

管理后台不承担以下职责：

- 不面向普通用户开放
- 不作为用户控制台使用
- 不直接成为账务规则和网关逻辑的第二实现
- 不在第一版承载复杂 BI、审批流或财务系统

## 2. 职责边界与上下游依赖

### 2.1 职责边界

管理后台是内部治理面，通过受控接口操作核心模块。

后台可以：

- 修改模型路由配置
- 管理套餐定义
- 查询和处理订单
- 调整账户状态
- 查询 usage 汇总

后台不应：

- 直接修改数据库绕过业务校验
- 自定义一套与计费核心冲突的状态规则
- 直接处理外部用户 API 请求

### 2.2 上下游依赖

管理后台依赖：

- 认证与权限系统：提供后台登录与角色识别
- API 代理网关配置能力：提供模型路由管理接口
- 计费与订阅核心：提供套餐、订单、账户状态、人工修正接口
- usage 汇总能力：提供运营查询视图

## 3. 功能拆分

### 3.1 模型与路由配置管理

后台应支持管理以下配置：

- 对外模型名
- 协议类型
- 上游供应商
- 上游真实模型标识
- 上游凭证引用
- 启用/停用状态

目标是支持：

- 新模型上线
- 异常模型下线
- 上游映射调整

第一版不要求复杂可视化拓扑或自动编排。

### 3.2 套餐与产品配置管理

后台应支持：

- 创建和编辑套餐定义
- 设置套餐价格、周期、额度、速率限制
- 设置套餐是否对外可售
- 下架旧套餐

套餐配置变更必须和现有订单、现有账户权益的兼容性保持清晰，不得直接破坏已生效套餐。

### 3.3 订单与账户处理

后台应支持：

- 查看订单列表和订单详情
- 识别异常订单
- 执行人工补单
- 调整账户当前套餐
- 暂停或恢复账户
- 封禁或恢复 API Key

### 3.4 运营汇总视图

后台应提供基础查询视图，包括：

- 账户列表
- 订单汇总
- 当前周期 usage 汇总
- 关键异常状态统计

第一版以运营支撑为目标，不追求复杂图表系统。

## 4. 核心数据对象

后台主要消费和操作以下对象：

- 路由配置对象
- 套餐定义对象
- 订单对象
- 账户权益状态对象
- API Key 状态对象
- usage 汇总对象

后台对敏感对象的展示应遵循最小暴露原则，例如上游凭证只展示引用关系，不大面积展示明文。

## 5. 关键接口与操作动作

后台至少需要以下受控能力：

- 查询和更新模型路由配置
- 查询和更新套餐定义
- 查询订单详情
- 执行订单补单或状态修正
- 查询账户权益状态
- 执行账户暂停与恢复
- 查询并管理 API Key 状态
- 查询 usage 汇总

所有高风险写操作应具备明确的操作入口和审计记录。

## 6. 关键流程

### 6.1 模型路由维护

1. 运营或管理员进入路由配置页面
2. 查看当前模型与上游映射
3. 新增、修改或停用某条路由
4. 系统记录操作日志
5. 更新结果生效到网关侧配置源

### 6.2 异常订单补单

1. 运营查看订单列表发现异常订单
2. 进入订单详情核验支付状态
3. 若确认已支付未开通，则发起人工补单
4. 计费核心执行权益修正
5. 后台记录补单人、补单时间和原因

### 6.3 账户暂停与恢复

1. 运营进入账户详情
2. 查看当前套餐状态、usage 汇总和异常原因
3. 执行暂停或恢复操作
4. 系统将变更同步到可调用状态判断链路
5. 后台保留完整审计记录

## 7. 权限、安全与审计

后台应至少具备基础角色区分，例如：

- 运营角色：查看订单、处理补单、查看账户
- 技术运营角色：管理模型路由、查看网关相关状态
- 管理员角色：执行高风险账户状态调整和关键配置变更

安全要求至少包括：

- 独立后台登录入口
- 严格身份校验
- 关键操作日志
- 敏感字段脱敏展示
- 高风险操作可追溯

## 8. 异常处理

后台是人工兜底入口，至少要能覆盖以下场景：

- 支付成功但套餐未激活
- 订单状态异常
- 模型路由错误导致服务不可用
- API Key 异常调用需要封禁
- 账户状态需要人工恢复
- usage 汇总异常需要进一步排查

后台界面应优先提供明确状态与后续动作，而不是只显示原始技术错误。

## 9. MVP 范围内与范围外

### 9.1 MVP 范围内

- 模型路由配置管理
- 套餐配置管理
- 订单查询与补单
- 账户状态调整
- API Key 状态管理
- 账户、订单、usage 基础汇总视图

### 9.2 MVP 范围外

- 复杂审批流
- BI 分析系统
- 财务结算系统
- 多层级组织权限体系
- 自动化运营策略系统

## 10. 测试与验收重点

管理后台模块至少验证：

- 路由配置变更能正确生效
- 套餐配置变更不会破坏现有已生效权益
- 异常订单可被人工补单并留痕
- 账户暂停与恢复会影响网关可调用性判断
- 不同角色的可见范围和可操作范围正确
- 关键操作审计日志完整可追溯
